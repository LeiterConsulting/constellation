# Product direction

The primary experience is a dashboard canvas and one conversation. Users should be able to start with a question, inspect actual Splunk fields, refine a selected element and keep their work without navigating a setup wizard.

## Interaction principles

- Begin with an empty canvas and data the current user can search.
- Ask for missing meaning, units or intent when needed; do not treat field names as proof.
- Keep requirements, page purpose and focus with the draft.
- Offer editable follow-ons that identify what they would change.
- Show real progress, bounded validation and clear Stop/save state.
- Preserve unrelated/unknown native work and keep failure recovery visible.
- Use native Splunk controls and permissions for the final dashboard.
- Reveal technical detail when it helps a user decide or recover.

These are design principles, not measured usability results. The [roadmap](roadmap.md) records remaining work; the [support policy](support-policy.md) defines 1.0's actual scope.

The earlier [product research](history/product-direction.md) is retained as history. Its options and comparisons are not installed features or promised delivery dates.
