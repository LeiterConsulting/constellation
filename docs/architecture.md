# Architecture

Constellation is a Splunk app with an embedded browser workspace and current-user Python REST handlers. It does not require a separately deployed orchestration platform, database or vector service.

## Wide-event inspection and packaged runtime (0.31)

Discovery uses the existing field-role ordering before the 100-field native response cap, then the existing 60-field agent context cap. It excludes `_raw` and retains an intact leading row sample within the one-million-byte JSON result bound. If extracted fields still exceed that bound, completion is partial and counts describe only retained rows. One oversized extracted row fails explicitly. No value is shortened or coerced to fit. Ordinary preview jobs and dashboard validation retain strict oversize rejection, current-user scope and the existing row/time limits. `preview_jobs.py` owns this internal discovery path; `field_context.py` owns field ordering and metadata; `search_evidence.py` allowlists its fixed partial reason.

`data_service.py` rejects changed real-data bindings with unquoted SPL-style `eval`/`sort` commands and supplies search-side recovery guidance. Quoted strings and unchanged unknown expressions remain intact; this does not claim complete DOS validation. `native_transport.py` recognizes Splunk's connection-exception wrapper, keeping service interruptions outside model/query repair. Existing read eligibility, one retry, original deadline and mutation/inference non-replay remain unchanged.

`table_sort.py` recognizes an explicit literal sort of the selected table by one verified output field. On an exclusive SPL search it proposes only an appended sort, retaining all native bindings, columns, handlers, geometry and unknown properties. This local proposal uses the ordinary authoring compiler and every final validator without a model call. Compound requests, files, unverified outputs, shared/chain dependencies and SPL2 retain model editing. A local validation/service failure is not silently accepted; ordinary recovery or interruption rules apply. This grammar is an explicit compiler boundary, not a general natural-language intent classifier.

`quick_edit.py` also handles one exact existing-return-button label request when its stated destination already matches one unambiguous native page. Only the label changes; existing width must fit. Navigation changes, files, ambiguous targets, compound requests and unplaced/global buttons keep ordinary authoring. This presentation-only edit needs neither inference nor a data search.

`SearchService.datasets()` shares a defensive metadata snapshot only within the runtime created for one authenticated REST request. Initial catalog, profile and repair no longer enumerate indexes repeatedly in that turn. New requests/users receive fresh runtimes; no catalog, event, permission or query-result cache is shared across sessions. Restricted/disabled/metric metadata retains its original meaning. Field inspection and actual search authorization/execution remain fresh and bounded. This reduces duplicate calls to an observed slow native endpoint; it does not establish the root cause of every native transport timeout.

`scripts/package_runtime.py` adds a public runtime content fingerprint to each packaged persistent driver's environment. [Splunk's persistent-driver contract](https://help.splunk.com/en/splunk-enterprise/administer/admin-manual/10.4/configuration-file-reference/10.4.4-configuration-file-reference/restmap.conf) permits processes to be shared across endpoints with the same driver configuration. Live in-place reinstall testing retained old imported behavior after an entry rename; driver revision pinning loaded the changed behavior. It complements content-derived entry names while preserving separate control, shared-AITK and owner-only-OpenAI configurations. It changes no endpoint, capability or token contract. Verify loaded behavior after installation; upgrades during active authoring and cross-member deployment still need separate coordination.

## Calculation-specific compact recipes (0.30)

`creation_recipes.py` exposes three strict wire forms: stats has metrics and a grouping field; timechart has metrics; raw table has columns. The kind discriminates required properties, so aggregate plans do not carry a raw-column list. The compiler supplies only omitted inapplicable empty values and retains compatibility with the former complete form. Populated irrelevant fields, unknown properties, invalid inputs, aliases, types and unsupported calculations still fail. No model field is silently discarded to pass validation.

Eligible Ollama creation now prefers these recipes inside the existing flat, page-indexed chart list. AITK retains its composition with the same smaller recipes. Both retain a pipeline/x/y alternative for calculations outside the recipe functions; advanced, supplied-query, SPL2 and existing native editing boundaries remain unchanged. Recipes own neither data execution nor acceptance: scope, measurement masks/populations, actual output, original intent, placement, navigation and preservation checks still run before atomic commit. No UI, credential, persistence schema, execution authority or recovery-budget changes are introduced.

## Bounded Ollama outline and unit context (0.29)

Ollama's eligible compact first draft uses `creation_outline.py`: a flat chart list with zero-based page membership and a separate page-label/purpose list. An explicitly exact total constrains the one chart array in the model schema and remains checked at runtime. The compiler neither invents missing panels nor truncates extras; malformed memberships, unknown fields and empty pages fail. It expands into the existing composition, searches, chart bindings and navigation, retaining all actual search/output, scope, measurement, placement, intent and permission validation. AITK keeps its recipe strategy; OpenAI and advanced/existing edits keep their established paths. Recovery still uses three model calls, sixteen query checks and the existing time bounds.

When an eligible compact first draft fails a late search/binding check, its rejected composition remains transient. `agent_service.py` resets that uncommitted candidate to the exact original empty document and requests a corrected complete compact plan, retaining scoped evidence, request-local search caching and the short output allowance. It does not expand a small failure into native JSON editing just because staging preceded validation. Every original-goal, output, search, measurement, navigation and placement check runs again before atomic acceptance. Existing/imported work, advanced/native requests and staged noncompact creation retain their ordinary repair paths.

The compact compiler can remove a redundant terminal timechart grouping only on a linked destination's single verified row-selection field, when fixed chart bindings exactly match its ordinary literal aggregate aliases. It requires a catalog SPL scope, a fresh composition and an ordinary timechart header. Overview sources, explicit split-series requests, supplied searches, derived expressions, quoted fields, advanced options and post-timechart transforms retain their ordinary paths. Native output, default/two-selection arithmetic and scope still require validation; this is not a general grouping rewrite.

An explicit requirement to keep all source observations is retained in the existing user brief and exposed as request-local `retainSourceRows` intent. With the verified temperature mask already enforcing the exclusion, exact redundant pre-aggregate cutoffs are removed even in temperature-only queries. Remaining ambiguous temperature row filters are rejected with recovery feedback; ordinary entity selection remains allowed. Unknown predicates are never silently deleted, unchanged sources remain preserved, and an explicit shared-population revision keeps its separate semantics. Recipe-shape feedback identifies columns, metric-count or timechart-grouping errors separately.

`field_context.py` recognizes exact-field assertions such as `temperature_f is stored in Fahrenheit` and `wifi_rssi is in dBm`, alongside recorded/measured-unit declarations. Definitions remain scoped to the selected data and persist through the existing sidecar; no migration runs. Questions, hypotheses, alternatives, negative assertions and requests to display/convert units do not declare a stored unit. Physical units are never inferred from a cutoff. Optional suggestion filtering in `promptEvidence.ts` omits repeated recorded-unit questions only with scoped user evidence, retaining undefined fields, name conflicts and display-conversion requests. Definition changes invalidate stale suggestions. The canvas and conversation gain no control.

## First-draft searches and page scope (0.28)

The AITK compact strategy enables recipes; Ollama retains its previously qualified pipeline format after live recipe-union trials failed chart-count validation. This is an explicit tested strategy, not an inferred model capability. `creation_recipes.py` compiles small verified SPL plans for stats, timechart and raw tables. One plan defines input fields, aggregate functions, aliases and native chart bindings together; counts of events and counts of valid measurements remain distinct. New aggregate table recipes append pure self-rounding to two decimal places and format verified timestamp aggregates; count fields remain integers and chart series retain numeric values. Recipe metrics use the verified measurement directly, with existing source masks enforcing exclusions. Literal fields, numeric provenance, aliases, grouping and shape are checked before compilation. Native catalog `_time` retains timestamp semantics when a verbose sample serializes it as text; arbitrary supplied queries receive no such exception. Raw pipelines remain available for unsupported calculations. The existing actual-search/output, scope, missing-data, population, placement, version and recovery checks remain mandatory. Numerical `recovery.recipePanels` reports how many panels were compiled from a recipe in the turn; it is not an analytical acceptance score.

`creation_page_scope.py` treats an ordinary first-draft table row mapping as selection for its destination page. It reuses the route compiler to filter all ordinary destination searches and clone shared sources, removing only the exact corresponding pre-aggregation row clause from the origin's new source. Other predicates, measurement masks, ranges, properties, handlers and focus remain. The module requires a verified field, one wildcard-default row token and ordinary absolute pages/SPL sources. It does not rewrite existing/imported dashboards, input-owned selection tokens, deliberate shared/global/selective requests or advanced/ambiguous dependencies. Those retain ordinary native editing and validation. No natural-language wording to preserve Overview is needed for the supported default.

`table_projection.compile_creation_columns` keeps an explicit verified raw-field list on one unambiguous fresh table. It can extend a positive literal projection and its simple native table binding, without changing grain or other columns. Removed/computed fields, negative projections, aggregates, multiple/shared raw tables and advanced DOS expressions are not invented or rewritten. Native output and the final raw-column validator still decide acceptance. No settings controls, execution privileges, draft migrations or recovery-budget increases are introduced.

## Compact creation syntax (0.27)

`compact_creation.py` reuses `formatting_syntax.repair_query` only for a fresh composition table's own SPL pipeline. It inserts missing separators only when an entire post-stats eval command consists of recognized self-round/strftime assignments. Expression and quoted-format bytes are retained. Raw-event stages, non-table charts, unknown expressions, non-SPL composition and existing native work retain their prior paths. Compiled searches still pass the same scope, measurement, output, feature, placement and actual-search validation before atomic acceptance.

Compact guidance prefers one assignment per eval command, explicitly explains comma separation and uses double-quoted string literals. Controlled native EvalCommand feedback now names both comma and quote rules without returning native error bodies. This targets a recognized syntax failure class; it does not establish that every historical eval failure had the same cause or turn unknown expressions into accepted syntax. No provider/privileged handler, budget, draft schema or UI control changes. The [Splunk eval reference](https://help.splunk.com/en/splunk-enterprise/search/spl-search-reference/10.2/search-commands/eval) documents comma-separated assignments and quoted literals.

## Pending save recovery (0.26)

`draftRecovery.ts` holds one pending snapshot in this tab's `sessionStorage`, limited to 1.5 million JSON characters and six hours. It checkpoints visible changes before the autosave debounce. Startup obtains the authenticated owner from the existing draft listing before reading recovery state; a different account, malformed/expired entry, deleted draft or missing previously saved draft is not restored. There is no browser connection/key cache, indexed-row cache, new endpoint or external worker. Draft contents, including conversation, SPL and small pending attachments, are sensitive browser content: see [security](../SECURITY.md#drafts-and-retention).

`DraftSync` compares object content independently of key order. Lost save delivery triggers readback, never a blind write retry. Exact saved content confirms the write. A pending snapshot keeps the last confirmed version and the exact issued intermediate write. After refresh, a committed intermediate write advances that base only when both its next revision and complete contents match. If it commits just after the refresh read, one definite revision conflict may be reconciled by the same exact proof, followed by one compare-and-save of the latest local snapshot. Another session's different content or later revision still conflicts; local work remains available through the existing save-as-copy action. All writes still undergo native draft validation, ownership and local locking.

The recovery copy clears after confirmed save. If browser storage is blocked/full or the snapshot is too large, the existing save line says to keep this tab open until saved and the unload warning remains. Closing a tab, expiry, browser eviction and large attachments are not durable recovery guarantees. Private Splunk drafts remain the cross-session source of truth. Interrupted inference stays as pending user input and is never dispatched automatically. Draft schema stays 3. Startup storage failure now keeps editing disabled with a single Retry loading drafts action instead of autosaving a replacement blank draft.

Stop sends at most one cancellation for a created handle and starts no run for an already-aborted signal. These changes do not make blocking upstream provider calls preemptible, add streaming or qualify distributed search-head routing.

## Delivery recovery (0.25)

`src/restDelivery.ts` defines the explicit read allowlist and one-retry deadline policy shared by app requests and native readback. Discovery/profile/preview reads, draft reads, and control/result polling can recover a transient connection or gateway failure. Start/dispatch, inference, settings/draft writes, native saves, login/permission failures and validation errors are never replayed. A retry consumes the original deadline rather than resetting it. Transport details and response bodies do not enter user-facing errors.

`authoringRun.ts` keeps the original single author dispatch separate from validated-reply retrieval. After an original delivery failure it waits for the already-running handler through the existing control endpoint; a successful original response, a validated reply, Stop, a terminal handler failure or the 240-second delivery deadline ends that wait. Stop also rejects the pending delivery promise, so loss of the original response cannot strand cancellation. The existing progress line can show Reconnecting to Splunk. There is no background worker or automatic inference retry.

`native_transport.py` permits one retry for GETs and the exact owned v2 search-results POST, within the existing native request timeout. Search creation, job controls and privileged provider completions are not eligible. Permission and certificate errors are not retried. `SearchService` classifies exhausted transport as HTTP 503; data validation and authoring propagate it instead of treating it as invalid SPL or spending a model repair. Native and browser deadlines, server recovery budgets and provider call limits remain distinct.

Creation retains the same bounded grammar: named/distinct/separate page adjectives can qualify an explicit count. A focused fixed-rectangle button plan preflights an explicit literal label that cannot fit. An explicit raw-table field list on an otherwise blank verified SPL canvas checks actual output and visible projection for one eligible unaggregated table. These checks do not infer arbitrary query semantics, rewrite existing work or change permissions.

## Request flow

1. The React workspace gathers the current definition, revision, active page, explicit selection, request and bounded conversation context.
2. The server checks environment capabilities and selected data scope, profiles field metadata, and retrieves a bounded set of bundled guidance.
3. A provider adapter shapes the request for OpenAI, Ollama or AITK.
4. Typed authoring actions compile to native Studio set/remove operations. The server validates structure, references, versions, layout and supported safety constraints.
5. New/changed real-data searches execute under the current user's permissions. Controlled diagnostics and metadata can drive up to two repairs after the initial response.
6. Only a valid final candidate is applied atomically against the client revision. The canvas renders it and enables bounded previews.
7. The private draft and conversation save independently in Splunk. Native Studio save is an explicit new-copy action with exact readback verification.

Provider messages, retrieved guidance, uploaded documents and indexed content are untrusted inputs. They cannot grant new permissions or bypass the deterministic edit/search boundary. The app does not execute provider-authored browser code or arbitrary Python.

## Persistence and authority

Optional shared AITK inference is a separate privileged boundary in `aitk_inference.py` and `AitkInferenceHandler`. The separate `aitk_connection_policy.py` module verifies protected AITK connection metadata and collection ACLs before a job is submitted. Its REST stanza and the separate owner-only OpenAI stanza receive Splunk's per-request system authentication; main/control handlers retain caller tokens exclusively. The default-disabled, app-owned `constellation_aitk.conf` policy must be writable only by administrators and pins one connection, execution user and role audience. The real caller must hold `constellation_use_aitk`, `search` and a configured role. No client can supply SPL, provider URLs, execution users or job identifiers. Prompt bytes are percent-encoded into a constant one-row `urldecode`/`ai` search; indexed searches never run in that worker. Output is limited to a normalized completion; tokens, native logs and job IDs are not returned. Admission slots are bounded to two per user/eight per search head with expiring metadata; uncertain native dispatch/process failures can outlive a slot, so this is not a strict native-job quota. Privileged REST calls have ten-second transport timeouts; cancellation rechecks the caller's signed authoring handle. Job cancellation/deletion is attempted on exit; native TTL and audit/history retention remain. Actual-data validation, drafts and native saves continue under caller permissions. See [administrator setup and review boundaries](aitk-setup.md#shared-inference-without-credential-read-access).

Owner-only OpenAI custody is separate in `openai_private.py`, `openai_private_handler.py`, `credential_store.py` and the caller-token proxy in `openai_connection.py`. Identity is rechecked with the caller token. Only that identity determines the encrypted record owner/ID; the privileged token never reaches the main/control handlers. The proxy returns validated settings with a key-presence marker. The private handler alone reads the saved key for fixed official model discovery or bounded structured inference. It repeats configured-model and inline attachment guards, forces `store:false`, and rejects tools, remote file references and arbitrary resource/owner parameters. Private placeholder ACL checks and existing-owner checks remain mandatory. Search, drafts and native output still use the author token. No draft or credential migration is needed.

Draft schema 3 separates the native definition from conversation, page purposes and session state. The current implementation uses private per-user custom configuration, a 200-record bound shared with Trash and an 11.5 MB snapshot bound. Future schemas cannot be overwritten by an older client. Interrupted inference is retained as pending user input and is not silently replayed.

Local file locking serializes writes on one search head; revision checks preserve conflicting local work. Search-head replication configuration does not provide distributed compare-and-swap. Cross-member concurrency remains unqualified.

Provider credentials use separate per-user IDs in Splunk's encrypted store, app scope, owner checks and empty read/write role grants. Administrators retain their platform authority. Private links identify a draft/page/element and require normal Splunk access; they do not grant sharing rights or embed event-derived form tokens.

## Resource limits and rendering

For bounded, text-only, two-page Ollama/AITK first drafts, `compact_creation.py` expands one short proposal into the existing typed actions. Pages retain model-selected names/purposes and one- or two-column layouts, while scoped searches, bindings and navigation are compiled by their existing modules. This creates a starting layout without duplicating chart/source/geometry fields in the model reply. It is available only on an empty verified SPL canvas, never for overwriting a working draft. Explicit geometry, advanced features, larger goals, SPL2 and existing dashboards retain the ordinary native actions. Repairs use those full actions against the exact staged candidate. Draft/native formats and validators are unchanged.

Explicit table-only formatting uses compact verified output metadata and dedicated guidance. Its generated schema lists only the selected table and verified numeric non-navigation fields; unverified/text fields cannot become formatting targets. No eligible output fails before inference. The full document stays server-side; the only admitted action compiles against that exact table/source receipt. Focused edits have editing-stage instructions rather than dashboard-completion instructions. During repair, a staged candidate replaces its duplicate wire proposal while preserving exact native configuration and feedback. `table_projection.py` can append an explicitly requested, returned alias to a simple terminal table projection. It preserves existing columns and revalidates features/bindings using the same search cache; unknown outputs and complex DOS expressions require ordinary repair. These changes reduce model work without adding interface panels or extending recovery budgets.

Authoring allows at most three model calls and sixteen unique search checks per turn. A 120-second budget is checked between operations; it cannot preempt an already-running provider request. Good and failed checks are cached for that turn. Search previews use at most eight sources, 200 rows and five seconds per query over a selected supported window. The job lifecycle verifies completion and labels resource-finalized, truncated or unverified output as partial; the selected window and query semantics still limit what those results mean.

The preview renders a clone through the actual Dashboard Framework. Native query definitions are preserved for export; screened results are substituted into the preview clone. Presentation edits reuse the query/language/range cache, while new or changed keys execute. Refresh clears the preview cache. Native rendering, schema validity, query execution and analytical correctness remain separate acceptance checks.

`usePreviewHeight.ts` measures the remaining viewport beneath the preview's controls, reserving space for status/save links and canvas padding. Resize observation handles wrapping and dynamically inserted controls; document coordinates prevent page scrolling from increasing the renderer height. The Framework fills this viewport and retains native page scrolling. Window resizing does not remount dashboard context or rewrite saved Studio dimensions.

Read [support](studio-support.md) for feature boundaries and [upgrade guide](upgrade-guide.md) for extension contracts.

## Starting questions and follow-ons (0.20)

The blank workspace inspects at most three candidate scopes sequentially through the existing current-user field-profile endpoint. It prefers the last selected scope within that workspace session, then distinct recently active event indexes. Discovery ranks public activity before internal logs inside its existing 120-row metadata shortlist. Metric indexes and catalog-only names do not become field-backed claims. The browser reuses metadata in memory for up to five minutes between inspection runs; it is not shared or persisted. Leaving the blank workspace aborts waiting and prevents further inspections; a native search already running retains its existing resource limits. No inference call is needed to prepare starter cards.

`datasetQuestions.ts` supplies conservative schema-based templates for measurements, response times, entity comparisons and outcomes. It does not infer business meaning from index names, inspect event values, assume failure status values, establish units/relationships or claim analytical findings. Primary temperature fields are distinguished from named summary fields; aggregate-only output retains its existing grain and cannot imply a time axis. An unsuitable or failed profile can yield no card. Selecting a question chooses its scope and fills the composer without starting inference or opening another form.

`prompts.ts` combines optional model cards with eligible local follow-ons, using brief, recent user requests, focus and active page. Exact repeats, known generic filler and explicitly declined suggestions are omitted. This is a bounded preference/eligibility heuristic, not complete natural-language understanding. Suggestion keys include conversation and standing intent, preventing stale proposals after those change. Displayed cards persist in the existing suggestion sidecar; oversized retry text stays in the composer and conversation instead. Author replies can return their metadata-only profile for local eligibility; profiles and result caches remain outside draft snapshots. All selected suggestions execute only through the ordinary authoring, scope, query and native validators. Shared creation guidance and compact focused/format guidance preserve their existing model budgets.

`search_hints.py` supplies controlled feedback when a timed-out changed SPL source uses automatic numeric `bin ... bins=N`. Creation guidance favors an explicit bin width in recorded units, or a verified summary/clarification when units are unknown. It does not rewrite searches, choose a business threshold, truncate events, expand the time range or increase preview limits. Other failures, fixed-span queries, quoted command text and SPL2 retain ordinary feedback. Native checks still decide acceptance.

## Brief, versions and search lifecycle

The brief stores the first user goal and explicit standing requirements in the user's words. Conservative phrase matching retains later unit/exclusion/standing instructions; it is not a complete natural-language requirements extractor. The user can review/edit purpose and requirements under More → Draft details. Verified data scope and page purposes remain separate sidecars in model context. The brief is untrusted user intent, not permission to bypass tools or evidence that every business rule was proven.

Material changes to definition, brief, page purposes or data scope retain the previous material revision in the same configuration-stanza write. History keeps at most ten versions within 4 MB, independently of the 11.5 MB current snapshot. It excludes conversations, file contents, result caches and tokens. Restore checks ownership and the current version, keeps today's conversation, clears transient focus/filter state and saves the version being left behind. Typing or selection alone does not consume history. Conflicts preserve local work; local locking still does not establish distributed SHC coordination.

Preview jobs use the normal v2 search endpoint with a five-second runtime cap, 10,000-event finalization threshold, 30-second inactivity cancellation, 60-second retention and native current-user search quotas. Signed handles bind an app-created SID, scope and expiry to the current user/session; poll rechecks native owner/app. No registry or new service is required. Results are fetched only after a terminal state, capped to 200 rows with a 201st-row truncation check, then the job is cancelled. Client Stop/pause, query changes and unmount cancel outstanding jobs, including a race with job creation. Closing a tab can interrupt cleanup; server limits remain the backstop.

Only positive completion metadata with no finalization, truncation or reported diagnostics earns a complete label. Missing evidence is partial, not complete. Results become stale after a minute or when paused; this is snapshot freshness, not automatic refresh. Search details hold per-source evidence and timestamps. Internal field inspection and authoring validation use the same lifecycle and return schema/controlled diagnostics without event values to the model. A partial zero-row inspection cannot establish an empty index.

## Sharing-preview contracts (0.9)

Repairs use an uncommitted candidate and accumulated edits, bounded to 64 total operations. Structurally valid candidate edits are retained for the next repair; every feature, intent and real-data search check still compares the resulting document against the original user document. No failed candidate is persisted or shown as accepted. Recovery feedback names its explicit candidate base and provides bounded placement hints; hints do not execute themselves. Exact typed geometry in a structure edit is converted to native geometry while retaining existing item properties. Changed absolute buttons can grow to the minimum readable height only when canvas bounds and neighboring content allow it.

Private user-namespace draft creation does not require rewriting ACLs. Every readback verifies the owner, app and private sharing, including the last-opened preference. Secretless Ollama/AITK preferences use a separate owner-private configuration collection; key-containing configurations remain in encrypted storage. Strict preference fields exclude keys. No runtime identity or role escalation is introduced.

Native save targets a selected app under the current owner and verifies app, owner, private sharing and exact definition readback. Output contains the original native sources and layout, with no Constellation script or service dependency. App context can affect macros, lookups, saved searches and modules. Native copies, working drafts and conversations have separate lifecycles; native edits do not silently overwrite a draft.

## Provider readiness and staged creation (0.10)

Settings separates a small structured-response test from full authoring acceptance. Diagnostics allowlist context metadata and numerical usage; unknown OpenAI/AITK capacities remain unknown. AITK retains model/credential custody. Empty AITK completions and provider output/context limits have controlled, actionable errors. Ollama and AITK recovery messages distinguish prior untrusted assistant proposals from current validation feedback.

Real-data search actions supply only a pipeline; the compiler binds the verified base scope, language and rolling range. Chart actions compile output field names into native DOS expressions. Explicit field-reference repair shapes are normalized only for changed channels backed by actual searches, then checked against executed output. Successful checks are reused and independent failures are combined for the next repair. The exact invalid SPL event-count shorthand `count() AS alias` compiles to an event count only in changed aggregate queries; quoted text, field counts, wildcard aliases, untouched queries and SPL2 are preserved. Recovery keeps the latest failed reply and current candidate instead of accumulating every rejected reply.

Bounded two-page AITK creation with an inspected dataset and at most 36 KB of serialized context attempts a complete proposal first. Larger/ambiguous AITK work and Ollama with unknown or sub-32K capacity retain a smaller foundation followed by completion. Verified 32K-or-larger Ollama models attempt a complete proposal first, reserving both repairs within the same three-call budget. The AITK threshold is a workload heuristic, not a verified token-window measurement. Stages consume the same three-call/120-second turn budget, not an additional unbounded loop. A later stage can reuse this turn's foundation page identity when its unique label matches; existing-user dashboard editing does not perform that aliasing. The complete candidate must satisfy original page/navigation intent and all data/feature checks before publication to the canvas. No partial foundation is saved as accepted work. Context budgeting uses a conservative byte estimate rather than a tokenizer; it never claims a verified provider token count and never drops the durable brief or native definition.

## Focused editing and typed filtering (0.11)

`focused_prompt.py` supplies a compact instruction set when a visualization/input is selected. The full schema and the same feature, scope, query, placement and intent validators remain in force. It changes guidance size, not authority or retry limits. Failure responses include numerical model/search counts and elapsed time; the client allowlists those numbers into the existing Activity disclosure.

Typed dashboard metadata compiles to targeted title/description changes. A typed entity filter requires an exact verified source field and safe token name, retains the inspected base scope and inserts a quoted native SPL `search` filter before aggregation. It is idempotent for its exact generated clause and preserves unrelated sources/properties. The builder supports `ds.search` SPL; SPL2 and chain queries retain their targeted native-edit path. Existing arbitrary queries are not rewritten into a different language.

New/revised queries with an all-value token default are screened for the narrow `where FIELD=$TOKEN|s$` literal-asterisk trap. Explicit all-value guards are allowed. This is actionable validation rather than a general semantic proof. Untouched imported query text is preserved. New page items referring to a same-batch typed button defer that redundant placement to the button compiler; conflicting placement pages and other missing references still fail atomically.

For new/revised SPL, an exact entity-equality predicate can be compiled locally when verified native table-row token mapping, destination page placement, source binding and an all-value default establish its intent. Other AND predicates remain verbatim; OR/complex predicates stay for validation. Normalizers run sequentially so a row-filter repair cannot overwrite a count-syntax repair. Untouched imported queries are excluded.

`population_guard.py` separately recognizes a narrow explicit independent-measurement request in the user prompt/brief. For changed SPL suffixes it rejects a shared aggregate that filters one verified numeric measurement globally before also calculating another. Feedback asks for conditional aggregation while preserving the cutoff. Exact existing-search scope, unmodified sources and SPL2 are not rewritten. Intent matching and syntax checks are deliberately conservative; derived-field relationships, reverse/complex predicates and general business semantics still need broader qualification.


## Responsive authoring (0.12)

The browser creates a one-use, session-signed run handle through `constellation/control/run`, then submits the ordinary atomic author request with that handle. Short polling/Stop calls use a separate persistconn driver configuration so synchronous inference cannot block controls. `authoring_progress.py` stores only allowlisted stage codes, numerical timing/attempts and opaque ownership hashes under Splunk's private runtime directory. No prompt, definition, result, credential or provider error is written there. Receipts expire after five minutes, are cleaned on start, and are capped to 512 retained receipts / two unfinished runs per session. Cancelled in-flight requests still occupy a slot until the author handler exits. Execution claims prevent replay; an expired/missing handle fails closed. This state is local to one search head, not a durable job system or an SHC coordination guarantee.

Stop immediately prevents client application of a late result and sends an independent cancellation request. Server checkpoints stop further stages; AITK and validation-search polling release native jobs in `finally`. A blocking direct provider HTTP call can still complete upstream and bill. Closing a tab or a failed cancellation transport can prevent the stop signal reaching Splunk; existing time/resource limits remain the backstop. Refresh does not replay inference.

`quick_edit.py` recognizes only complete, exact instructions for a selected chart rename or a line/area switch with a rename. It preserves all unmentioned native properties, runs the native edit validator, and returns zero model/search calls. Extra instructions, attachments, other conversions and ambiguous prose use the normal authoring path. This grammar is deliberately narrow; it is not general intent detection. First-turn authoring no longer waits for the client-only SPL2 probe; the server still checks the environment, and Environment can explicitly run the probe.

The compact toolbar keeps source/time visible and moves range, refresh/pause and per-source evidence into an accessible popover. Focus selection uses a disclosure; current focus remains visible. Progress has its own small component/timer, keeping the expensive dashboard renderer out of elapsed-time updates. The preview is also memoized against unchanged props so typing, dialogs and identical poll receipts do not request a full canvas render; data, tokens, focus, page and theme still update through their ordinary props/context. Splunk navigation and the original native dashboard geometry are retained.


For Ollama, the initial strategy now depends on live context metadata: a reported window of at least 32,768 tokens permits a complete typed proposal first, retaining two repairs. Smaller/unknown Ollama windows keep the foundation/completion strategy; bounded AITK work now uses the 0.14 strategy described below. The conservative context/output estimator and the three-call/120-second limits remain. This is a qualified strategy for the selected connection, not proof that every model with a large window authors well. Failure Activity retains up to three controlled validation messages so a final time-budget error does not hide preceding repair issues.

Persistent handler configuration follows the [Splunk restmap contract](https://help.splunk.com/en/splunk-enterprise/administer/admin-manual/10.2/configuration-file-reference/10.2.3-configuration-file-reference/restmap.conf); independent live control latency must still be verified on each supported deployment.

## Measurement and formatting contracts (0.13)

Only metadata, not values, enters model context. `formatTable` compiles number/date formatting into a final eval against existing numeric output aliases. It preserves the upstream aggregation, bindings, row-navigation fields and unknown properties, and rejects absent/nonnumeric columns or a shared chart source. An explicit table-only formatting request uses a restricted action schema, with runtime enforcement if a provider ignores that schema. Creation does not offer this existing-table-only action. Broader edits retain the full native authoring contract. Search changes revalidate existing visualization bindings even when the visualization itself is unchanged. Feedback identifies the actual missing/empty aliases and points recovery toward verified output fields.

The formatting-only classifier masks narrowly specified negative column/field preservation phrases, such as “do not add absent columns”; a later positive add/calculate/sort request still vetoes that route. `studio_features.py` also rejects newly introduced or modified `options.formatTable` properties, with feedback identifying the supported action or final SPL alternative. An unchanged imported property is retained. A saved/read-back option is not proof of native execution or of the requested visible format; verify timestamp and numeric display in Studio.

## Delivery recovery (0.18)

`authoring_delivery.py` keeps a validated success reply separately from stage-only receipts, under the same search-head-local lock and original session-signed run handle. Every run read/mutation also compares the stored session owner; signing a learned foreign nonce with a caller-owned key grants no access. Main/control handlers remain unprivileged. A completed reply contains the normal changes and metadata, including potentially sensitive dashboard/SPL content and the user-authored brief/goal; it never intentionally stores provider credentials, raw model replies, attachments or indexed result rows. Storage is mode 0700/0600, bounded to 1 MB per reply and 16 MB total, and expires with the five-minute run. Acknowledgement and Stop delete it; expiry removes access immediately and cleanup removes expired files on subsequent control activity/start. This is transient delivery support, not durable background execution or a replacement for private drafts.

The browser races the original author response with retrieval after a completed stage receipt. Retrieval cannot start a job, change the request or replay inference. Cross-search-head routing remains unqualified. Native HTTP 204 from an owned preview-results POST remains running within the existing preview deadline, without redispatching the search or relaxing output validation.

`formatting_syntax.py` corrects only missing commas between complete self-formatting `round(field, precision)` / `strftime(field, literal)` assignments after aggregation, in a changed, exclusive, selected existing SPL table source. It preserves expression bytes and quoted literals. Raw-event stages, boolean/arithmetic/unknown expressions, SPL2, shared sources and untouched imports retain ordinary validation/repair. Every normalized query still executes and passes all normal scope, measurement and output-binding checks before acceptance.

Changed ordinary chart/input rectangles must fit declared absolute-page dimensions, including native structure/position edits. Shrinking a canvas cannot newly clip an unchanged in-bounds item. Dataset completeness and nullable schema are separate evidence in `search_evidence.py`.
