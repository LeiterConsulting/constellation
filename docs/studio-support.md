# Studio authoring and runtime support

The opt-in shared AITK handler separates inference authority from ordinary authors' search and credential permissions. It requires an administrator-owned policy and an explicit inference capability; default/direct AITK behavior remains current-user. This is an app-native privileged boundary requiring security review, not a claim that AITK's native `ai` command no longer needs credential access. Qualification results are recorded separately in [validation](validation.md).

Table formatting uses a verified authoring action that compiles to a final SPL `eval` against existing aggregate output fields. `formatTable` is not a native visualization option: newly introduced or changed `options.formatTable` objects are rejected with repair feedback, while unchanged imported properties are preserved. Check the visible timestamp/number result in native Studio in addition to definition readback.

This is the working support contract for the 0.24.0 development preview. Broad document authoring is implemented; complete native parity is not yet qualified. The preview uses the embedded Splunk Dashboard Framework and preserves the original Studio definition for export and native save.

## Remaining qualification work

Full native parity requires a versioned fixture matrix for visualization option schemas, conditional visibility, evaluated/search-result tokens, cascading/multiselect inputs, trellis, maps, network graphs, custom visualization frameworks, refresh policies, saved/module searches, and broader query-parameter behavior. Broader role/administrator isolation beyond the selected two-user checks, accessibility/reflow, search-head-cluster concurrency, streaming, verified related-dataset discovery, other provider adapters, AITK setup/qualification on the second target, Ollama vision qualification and bundle reduction also remain open. These are explicit gates rather than claims of completed support.

## Provider and attachment boundaries

Direct OpenAI now uses the owner-only handler described in [security](../SECURITY.md). Ordinary authors need no credential-store capability. Managed AITK uses its separately reviewed privileged boundary and an administrator-approved connection; direct/native AITK retains the current-user command and credential requirements described below. These paths must not be treated as equivalent.

OpenAI retains the fixed official Responses endpoint, verified TLS and store:false. Ollama uses only /api/tags, /api/show and /api/chat on the configured origin, rejects redirects and embedded credentials/paths, permits private-LAN HTTP, requires HTTPS for public origins, and rejects link-local/metadata, unspecified, multicast and reserved targets. No OpenAI credential is sent to Ollama. IPv4/IPv6 loopback are supported. Vision is checked against the exact selected model’s live /api/show metadata; PDFs are not sent to this route. The available local models are not all qualified authoring models.

AITK keeps its own credentials. Constellation supplies a named connection and one synthetic prompt row under the current user’s Splunk_ML_Toolkit namespace. It checks apply_ai_commander_command, validates returned JSON, bounds inference wait time, and cancels the job when finished or timed out. AITK’s configured model/output limits apply. Settings cannot verify those limits and calls them out explicitly; reasoning can consume a small output budget before visible content is returned. The route supports text only. Prompt-bearing searches follow normal Splunk job/history retention; this is distinct from OpenAI store:false. No indexed events are fed to these jobs. The unsuccessful connection check failed safely without creating a native connection or changing roles.

## Pages and focused conversation (0.7.0)

Pages uses native Studio tabs and absolute/grid layouts. The Pages dialog creates/renames pages and records their purposes in the private draft; conversational page actions can move existing elements and create native cross-page actions. Typed button actions create, place and link navigation in one step. Explicit move and navigation outcomes are checked against the resulting definition. Native table field drilldowns carry a row value into a destination token. Tokenized validation resolves current values/defaults locally and enforces safe substitution; event-derived values are not added to inference context.

Select element temporarily overlays visible visualizations and positioned absolute inputs with labeled focus buttons. Escape cancels selection. Conversation focus also lists every input and page, including grid/global inputs without a qualified exact DOM target. Page/element focus generates relevant local prompt suggestions without background inference. Copy link produces an owner-restricted draft/page/focus URL and strips form tokens; HTTP installations offer a selectable link when browser clipboard access is unavailable. Native exports retain page/token interactions, while app element focus is specific to Constellation.

Native references: [field-level table drilldowns](https://help.splunk.com/en/splunk-enterprise/create-dashboards-and-reports/dashboard-studio/9.4/add-dashboard-interactions/configure-field-level-drilldowns-in-a-table), [row-token mappings](https://help.splunk.com/en/splunk-enterprise/create-dashboards-and-reports/dashboard-studio/9.0/add-dashboard-interactions/setting-tokens-on-a-visualization-click), and [tabbed definitions](https://help.splunk.com/en/splunk-enterprise/create-dashboards-and-reports/dashboard-studio/10.4/source-code-editor/what-is-a-dashboard-definition).

## Model-aware creation (0.10)

Scoped search, chart and token actions compile to ordinary native Studio configuration. Actual output-field validation still applies. New real-data multi-page AITK creation and Ollama models with unknown or smaller context windows use two internal stages and the existing recovery budget; no stage reaches the accepted draft on failure. Ollama capacity metadata bounds the requested context/output allocation. Conservative size estimates can trim rolling history while retaining the durable brief and definition. Settings exposes known/unknown capacities, small-test scope and allowlisted usage. A passing connection test does not establish full creation reliability; see [validation](validation.md) for tested models and budgets.

## Focused editing and analytical checks (0.11)

Dashboard text and verified SPL entity filters have typed builders. Selected chart/input edits use compact guidance with the same validators. Exact raw native text/binding strings can be encoded on known paths before output-field validation; malformed containers/quoted JSON remain errors. Native table-row intent can repair an exact new entity-equality filter, retaining other AND conditions. Complex/OR expressions and unknown relationships are not silently rewritten.

An explicit independent-measurement request enables a conservative shared-aggregate population guard for changed SPL. It catches a numeric measurement filter placed before another measurement's aggregate; conditional aggregation retains the other population. It does not prove general business semantics, cover all derived/reverse/complex predicates or extend that proof to SPL2. Existing query scopes and untouched imported sources remain preserved. See the [qualification protocol](provider-qualification.md) and recorded failures before deciding on broader support.


## Measurement and table formatting (0.13)

Explicit upper Fahrenheit exclusions bound to verified numeric temperature fields compile at the measurement boundary for changed scoped SPL. All ordinary null-ignoring aggregates share that population, while other event measurements remain available. Exactly-at-limit values are retained. Existing query scopes/untouched imports are preserved; general units, derived expressions and SPL2/chain business semantics remain outside this narrow guarantee. See [architecture](architecture.md#measurement-and-formatting-contracts-013).

Selected SPL table edits receive verified output-field/type metadata. Explicit table-only formatting uses an evidence-dependent typed action preserving the aggregation, aliases, bindings and row field. Missing/already-readable columns are not invented. Shared-source formatting and broader semantic changes require ordinary native editing; the typed action fails safely. Changed searches revalidate existing bindings even when chart configuration is unchanged.


## Visible table metrics

An explicit new aggregate alias requested for a selected table must appear in the verified search output and in its explicit `frameBySeriesNames` projection. Validation supplies repair feedback when the query calculates the metric but the table hides it. This narrow check recognizes simple aggregate expressions with `AS` aliases; it is not a general natural-language correctness proof. Explicit hidden/helper work and unchanged imported definitions are preserved. Native field existence, query scope, formatting and interaction checks still apply.


Sparse output: declared empty SPL columns may remain visible when conservative provenance connects them to inspected inputs, including a masked measurement followed by supported aggregation/formatting. A missing alias or unverified input still fails validation. This nullable-output exception does not qualify general SPL2 transformations or complete dataset coverage. Partial raw previews keep their native full query; the preview cap must not be compiled into a `head` or aggregation merely to hide partial status.

## Focused detail-page planning (0.23)

The exact suggested row-detail request for an existing selected SPL table uses one evidence-scoped `rowDetail` plan. The model chooses a verified raw row field and one to three chart pipelines; the app assigns collision-free IDs, full-width chart rows, safe pre-aggregation filters, wildcard defaults, table navigation and a placed Back button to the original page. Existing sources, projections and page geometry remain exact. Every native, actual-query, output-field, scope and measurement guard still runs. Failed detail plans are recompiled against the original document within the unchanged turn budget; no partial new page is published. General edited requests, existing navigation, ambiguous row fields, files and SPL2 retain their existing paths and qualification boundaries.

Wide tables in ordinary blank-canvas composition receive a full row rather than sharing a narrow column. Explicit geometry and existing dashboards retain their existing contracts. See [task benchmark](model-benchmark.md) for the synthetic regression protocol; a score does not authorize a model or establish native parity.
